# Density and variance: the measurement, and why no threshold was set

L-2026-07-31-b said the gate checks the ruled form of a style rule and not the
property the rule exists to protect. The backlog issue asked for six things. Five
are done. The sixth, fitting a threshold against the operator's corpus, is
refused on evidence, and this file is the evidence.

## What landed

`tools/prose_metrics.py` measures hyphen-compound density per word and sentence
length variance in both words and characters. `tools/slop_lint.py` calls it,
prints one `[density]` line, appends the row to `state/prose-scores.jsonl`, and
does not touch the exit code. 19 new tests in `tests/test_prose_metrics.py`,
350 passed across the suite in 113s.

The extractor is the part that carries the risk. Over raw markdown this repo's
own vocabulary poisons the metric: `--no-ignore`, `tools/slop_lint.py` and
`L-2026-07-31-b` all parse as hyphen compounds, so an ungated version would
mostly measure how much a document quotes code. That is L-2026-07-29-d wearing a
new number. `prose_of()` strips fenced and indented blocks, tables, inline code,
link URLs, bare URLs, paths, CLI flags, snake_case identifiers, lesson ids and
ISO dates, and a test pins each strip.

## The defect this shipped with for one hour

The first splitter cut a sentence at every newline. On a 4,287-word spec it
reported mean sentence length 7.5 words with a maximum of 21, for a document
whose sentences run past 40. It was measuring the author's wrap column. Every
variance figure computed before the fix was wrong, including the first corpus
sweep, whose `sent_words_sd` p50 of 3.8 is a statistic about hard wrapping and
nothing else. `paragraphs()` now rejoins wrapped lines, and
`test_hard_wrapped_sentence_is_one_sentence_not_three` holds it.

## Why the threshold is not set

The ticket said to fit against `voice-metrics/profiles.json`, n=35,472. That file
holds four profiles and all four are WhatsApp, scope `thread-level, both sides`,
median send near 20 characters. Banding a 5,000-word markdown document against
Hebrew chat sends is the error `profiles.py:118-121` already documents for
`line_cv`, and the module's own header calls the general case fake precision.

The alternative corpus is this repository's own 956 markdown files, and it is
circular: most of that prose was generated by the thing the gate is supposed to
catch. Fitting on it calibrates the gate to pass machine-written prose by
definition.

Measured over the 99 docs that clear 200 words and 5 sentences:

| metric | p10 | p50 | p90 |
|---|---|---|---|
| hyphen_rate | 1.27% | 2.73% | 5.71% |
| sent_words_mean | 11.2 | 14.9 | 18.5 |
| sent_words_sd | 6.9 | 10.0 | 13.6 |
| sent_words_cv | 0.585 | 0.681 | 0.814 |
| sent_chars_sd | 45.4 | 62.1 | 88.2 |

Now put the lesson's two numbers on that scale. The 2.8% hyphen density it cited
as the tell is the p50 of the corpus, dead centre. The 14.8 sentence standard
deviation sits just above p90, so in word terms it is unusually HIGH variance,
which is the opposite of the uniformity the tell is normally described as. One
of two things is true and the data here cannot separate them: either this whole
corpus reads as machine written, which is entirely possible given who wrote it,
or these two metrics do not discriminate at the values observed. Setting a
threshold before knowing which would be a guess with a decimal point on it.

So the collector runs warn-only, `state/prose-scores.jsonl` accumulates, and the
band gets fitted when there is a distribution to fit it from and an authored
reference to anchor it. Until then the standing instruction from the lesson
holds: a clean `slop_lint` is evidence about one banlist and one dash rule.

## Open

- No operator-authored long-form English exists in this repo at document length.
  `state/prompt-tickets.jsonl` stores `text_sha` only, not text, so the 229
  captured prompts cannot serve as a corpus either. Without an authored anchor
  the fit stays blocked no matter how much collector data accumulates.
- `sent_chars_sd` and `sent_words_sd` are both logged because the lesson's 14.8
  came without a unit and neither reading reproduces it exactly.
