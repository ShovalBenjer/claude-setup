# Documentation Archive

This directory holds retired documentation: superseded plans, closed analyses, and
historical records that are no longer maintained but must remain retrievable.

## Policy

- **Retired, not deleted.** Documents move here when they are superseded, closed, or
  no longer maintained. They remain in git history and in this tree for reference.
- **Migration notes required.** Every move into this directory must have a dated migration
  note explaining what was retired, why, and where its live replacement lives (if any).
- **No stubs.** Every document in this tree must have real content. Placeholder files are
  not permitted.
- **Archive is read-only.** Do not edit archived documents. If a document needs updating,
  it should be moved back to its live location or its replacement should be updated.

## Structure

```
docs/archive/
├── README.md                   This file. Archive policy and navigation.
├── MIGRATION-2026-08-24.md     Migration log for the mature documentation system pass.
├── HANDOFF-2026-07-31-review-oracle-repair.md  Retired handoff document.
├── 2026-07-24-creativity-wow-gap.md             Retired analysis (superseded by specs).
├── 2026-07-24-research-wiring-audit.md           Retired analysis (findings absorbed).
└── ...
```

## What belongs here

- Superseded specifications and plans.
- Dated analysis snapshots with no live referrer.
- Closed handoff documents.
- Retired research that has been absorbed into specs or standards.
- Historical records required for audit trail (e.g., supersession evidence).

## What does NOT belong here

- Active PRDs, specs, or ADRs (live in `docs/prd/`, `docs/specs/`, `docs/adr/`).
- Current standards or conventions (live in `docs/standards/`).
- Generated artifacts (live in `state/` or regenerated by tools).
- Source code or configuration (live in `tools/`, `dot-claude/`, etc.).

## Migration procedure

1. Identify the document to archive.
2. Verify it has no live referrers (run `python tools/map/codemap.py check` and
   `python tools/docmap/docmap.py check`).
3. Move the document to `docs/archive/`.
4. Update any references to point to the live replacement or remove them.
5. Write a migration note in `docs/archive/MIGRATION-YYYY-MM-DD.md`.
6. Regenerate `docs/DOCMAP.md` via `python tools/docmap/docmap.py write`.
7. Commit with message: `docs: archive <filename> - <reason>`.
