Architecture in One Line

Telegram / Chatwoot Incoming customer message
→
chatwoot_handler Filter + normalize + call agent
→
channel_router Foundry conversations + responses
Foundry Agent brand=seekapa by default
→
chatwoot_handler Send reply to same conversation
→
create_ticket Escalation path (labels + note + open)

Live Endpoints

1) chatwoot_handler (anonymous webhook)
POST https://func-cs-agents-dev.azurewebsites.net/api/chatwoot-webhook
2) channel_router (function auth)
POST https://func-cs-agents-dev.azurewebsites.net/api/channel-router?code=<FUNCTION_KEY>
3) create_ticket (function auth)
POST https://func-cs-agents-dev.azurewebsites.net/api/create-ticket?code=<FUNCTION_KEY>

Note: chatwoot_handler processes only event=message_created, incoming messages, non-private notes, sender.type=contact, and inbox in allowed set (4).
