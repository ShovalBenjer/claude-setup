# Spec — SLM Swarm (how we actually use small models)

Grounded in the 2025-2026 SLM literature (NVIDIA 2506.02153, FrugalGPT, RouteLLM,
xLAM/NuExtract, NeMo data-flywheel; rebuttals Self-MoA, MAST, SLM-in-loop 2607.05775).
The one operating rule: **frontier plans/decides/judges/drives the loop; a small stack
of fine-tuned/local specialists behind a calibrated router does bounded, format-locked,
high-volume leaf work; every SLM output is schema-checked; every uncertain case escalates.**

## The flywheel (NVIDIA S1-S6, adapted to this OS)
1. Log all non-conversational model calls — already have audit.jsonl, skill-usage,
   a2a-audit.
2. Curate + PII-strip after ~10k-100k examples (pii-scrub.py, pii-handling rule).
3. Cluster recurring task patterns (the coverage-cluster taxonomy from mojuco).
4. Pick a candidate SLM per cluster.
5. LoRA/QLoRA fine-tune (optionally distilling Claude's outputs on that cluster).
6. Eval vs held-out; promote the adapter only if it passes; iterate.
The OS already produces the training data as a side effect of running.

## Hardware fit (this machine, stress-tested 2026-07-23)
- Local CPU ceiling: 1.5B comfortable (13.8 tok/s), up to 14B-Q4 in ~11GB freed RAM
  (~2-4 tok/s, async only). Good for uses 1,2,4,7 at low volume.
- Fine-tuning (use 3) and any real serving throughput: rent an on-demand 4090/A100
  (ADR-0009), tear down after. Not DigitalOcean GPU (bills while off).

## Do NOT (from the rebuttal literature)
- No SLM driving a multi-hop loop; no symmetric debate/vote swarm; no SLM judge that
  gates a decision; no assuming local-cost-win at low volume.

## Acceptance
- [ ] Router (use 2) calibrated + logging kept-local decisions; feeds approval gate.
- [ ] One structured-extraction specialist (use 1) with schema-check + escalate.
- [ ] Flywheel S1-S3 running off real logs (collect + PII-strip + cluster).
- [ ] One trace-fine-tuned specialist (use 3) beating a held-out baseline before promotion.

## Tracer-bullet slices for the 5 unbuilt uses (added 2026-08-17 glue pass)

Use 2 is the only row with code (`tools/local/route_classify.py`, verified on
disk). The other five are TODO with no falsifier; this section adds one each.

1. **Use 1, structured extraction.** One local 0.5-4B model extracts a fixed
   JSON schema from one real input class (e.g. `state/prompt-tickets.jsonl`
   ticket text) with constrained decoding. Falsifiable: a schema-validation
   run against 20 real inputs passes on all 20 or logs an escalate row for
   each failure; zero silent schema violations.
2. **Use 3, trace-fed specialist.** A LoRA adapter trained on one clustered
   task type beats a held-out frontier baseline on that cluster.
   Falsifiable: `eval` output shows the adapter's score on a held-out set
   equal to or above the frontier baseline's score on the same set, both
   numbers pasted.
3. **Use 4, offline batch triage.** One overnight local-CPU run classifies a
   real batch (e.g. inbox or log rows) with an "uncertain" bucket routed to a
   frontier model. Falsifiable: the run's own output file has zero rows with
   no label and no escalate marker.
4. **Use 5, speculative decoding.** A drafter/verifier pair from the same
   model family runs on this machine's local tier. Falsifiable: measured
   tokens/sec with speculative decoding on beats the non-speculative baseline
   on the same prompt set, both numbers pasted, verifier output byte-identical
   to non-speculative output.
5. **Use 6/7, draft-then-verify and batch summarization.** A local 7-8B model
   drafts one artifact class (commit message or inventory scan) and a
   frontier call gates it before it lands. Falsifiable: 10 consecutive drafts
   show the frontier gate rejecting or editing at least one, proving the gate
   is not a rubber stamp.
