# Fog of war, measured 2026-08-01

Status: measurement, not a plan. Every number here was produced by a command
named beside it, and three of my own measurements were wrong before they were
right. Those corrections are kept in section 5 because a sweep that reports only
its final number is asking to be trusted rather than checked.

The operator's question was whether this repository is mostly scaffold: work
that is described, marked done, and not actually wired. The short answer is that
the documents are in better shape than feared and the tool tree is in worse, and
the two failures have opposite shapes.

## 1. Documents naming things that do not exist: 45 of 1,269, 3.5%

Across 38 documents in `docs/`, `docs/adr/` and `docs/prd/`, every repo-relative
path-shaped token was extracted and tested for existence. 20 of the 38 documents
name only paths that exist.

That is not a scaffold problem. It is close to what an actively edited estate
should look like, and it refutes the premise that most of the writing describes
vapour.

The exception is not statistical, it is structural, and one artifact carries it:

| Missing artifact | Named by |
|---|---|
| `state/ecosystem.db` | ADR-0011, ADR-0017, `docs/prd/autonomy-ecosystem.md`, `docs/prd/2026-07-30-consolidation-and-migration.md` |
| `tools/eco/db.py` | `docs/SYSTEM-MAP.md`, `docs/prd/autonomy-ecosystem.md` |

**ADR-0011 is titled "one operational state DB" and the database does not
exist.** Four documents reason on top of that decision, and `TODO.md` carries it
as AUTO-06 with two tickets blocked behind it (AUTO-04 work-claims, AUTO-19
FleetView). An accepted ADR whose artifact was never built is the single largest
piece of fog in the repository, and it is fog precisely because everything
downstream reads as coherent.

Reproduce: the sweep is in the session scratchpad, not committed, because a
one-off measurement script that becomes a tool is the failure section 2 is about.

## 2. Tools that exist and nothing invokes: 21 of 92, 23%

"Wired" here means something outside the file itself invokes it: a CI workflow,
`quality-contract.json`, a live hook or skill under `~/.claude`, a row in
`state/claims-verify.jsonl` whose `verify` field runs it, or `mutate.py`'s
`SPEC_DIR` loader.

| Class | Count | Meaning |
|---|---|---|
| ENFORCED | 38 | invoked by CI, the contract, a live hook, the falsifier registry, or the mutation loader |
| TESTED | 15 | not enforced, but a test names it |
| DOC ONLY | 18 | a document describes it, nothing runs it, no test covers it |
| ORPHAN | 21 | nothing outside the file names it at all |

The 21 orphans split into two classes that want opposite treatment, and
collapsing them is what makes the tree look like scaffold.

**Finished errands, roughly 950 lines.** `tools/workspace/` holds seven scripts
written to perform one operation once on the public GitHub estate: add an MIT
LICENSE to two repositories, repair a README that was a raw chat paste, cut the
first `claude-memes` release, polish another README to a case-study bar, log one
specific charter lesson, and two repo-activity queries. Their docstrings are
excellent and dated, they name what they verified, and they ran. They are
receipts, not instruments. Leaving them executable in `tools/` is why the tree
reports 92 tools when it operates about 60.

**Real utilities nobody wired, and one of them matters now.**
`tools/wsl/deploy_config.py` (208 lines) translates the live Windows `~/.claude`
into a working WSL one, which is exactly the deployment step that
`skills_sync.py` reports 49 items of drift against. `tools/reclaim/temp_sweep.py`
(177 lines) reclaims a measured 11.42 GiB. `tools/intent/scan_resources.py` (174
lines) backfills the resource ledger from 185 files nothing queries. Each is a
working tool with no caller.

**The connection worth naming.** `tools/workspace/log_session_lesson.py` writes
`state/lessons.jsonl`. It is an orphan one-shot. That ledger now holds 42 rows in
10 distinct key shapes, and `tools/digest/build_digest.py:89` reads
`r['enforcement']` unguarded against rows that do not have it, so the digest
build dies with `KeyError`. AUTO-16 exists to surface open lessons in every
digest and surfaces none. A writer nobody owns produced a shape nobody enforced,
and the reader broke silently. That is one causal chain, not three findings.

## 3. Zion is published, and its board state is unreadable

`ShovalBenjer/claude-setup` carries 31 issues, 30 open EPICs, matching the 33
epics in `state/github-backlog-2026-07-31.json` (project 3, "Zion"). So the
backlog shipped; the earlier note that writes were skipped is stale.

What cannot be read: `gh auth status` shows scopes `gist, read:org, repo,
workflow`, with no `read:project`. Column, priority and status fields on the
board are therefore invisible to any session, including this one. The backlog
file declares `Priority (P0-P3)`, `Ingestion (S1-S6)` and `Estimate` fields that
nothing local can verify are set. Fix is one command the operator must run:
`gh auth refresh -s read:project`.

## 4. The gate cannot certify the tree it leaves behind, third instance

`tools/gate/gate.py:238` defines `HARNESS_OUTPUTS` for files a turn of
conversation alone can change, holding `state/prompt-tickets.jsonl` and
`state/skill-use.jsonl`. `state/prose-scores.jsonl` is written once per response
by a live hook and is not in that tuple, so the fingerprint moves between a green
run and the Stop check that reads it.

The comment above the tuple already documents this class twice with dates and
measured fingerprints. This is the third instance, arriving the same way. The
comment even names the reproducible way to find the rest, which nobody has run:

```
git ls-files -z state/ | (report mtimes)
grep -rn "state/" ~/.claude/hooks/*.sh *.py
```

## 5. Three measurements of mine that were wrong first

Recorded because L-2026-07-31-c is a reviewer whose own numbers went unchecked.

1. **`.jsonl` read as missing.** The regex alternation `json|jsonl` matches
   `json` first, so every `.jsonl` reference in every document counted as a dead
   path. Inflated the document finding from 45 to well over 90.
2. **Relative paths resolved against the wrong root.** `docs/INDEX.md` names
   siblings as `adr/0001-....md`; resolving those against the repo root reported
   91 of 95 paths missing in the index alone. Both fixed before any count left
   the session.
3. **Circular evidence counted as wiring.** `state/reviews/<sha>.json` names a
   file only because it appeared in a diff, and `docs/prior-art/tools-*.json`
   exists *because* the file is over 300 lines. Counting either as "something
   names this tool" hid 15 orphans. In the opposite direction, a text search
   cannot see `mutate.py`'s `SPEC_DIR` path loader or the `verify` column in
   `state/claims-verify.jsonl`, so 16 mutation specs and 8 refute checks read as
   dead when all 24 are wired. The orphan count moved from 6 to 21 only after
   both errors were fixed, in opposite directions.

   counting as instruments.
5. **`gh auth refresh -s read:project`,** operator-only, one command, unblocks
   every future read of the board.
