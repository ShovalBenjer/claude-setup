## What was learned (non-obvious)

- **Foundry exposes the same agent through TWO surfaces with INDEPENDENT configs.** `/openai/v1/conversations` + `agent_reference` honors the agent registry version (PATCHable). `/applications/{name}/protocols/openai/responses` honors a portal-managed config that has no REST API surface and rejects per-request `reasoning`/`tools` overrides with HTTP 400 "Not allowed when agent is specified". `_should_use_application_endpoint()` in `channel_router` decides which one based on `AZURE_AI_FOUNDRY_ROUTE_MODE` + presence of `message_history`. Default `auto` sends Telegram traffic (which has history) to the application surface.
- **`az functionapp config appsettings delete` silently drops KV-referenced settings during round-trip.** Deleting 25 named-only settings caused 9 unrelated CRM env vars to also disappear, including a critical KV password reference. The CLI fetches existing settings, applies changes, PUTs the full collection — the merge step doesn't faithfully preserve KV refs. **Always count before/after.**
- **`az functionapp config appsettings list -o table` exposes secret VALUES in stdout** (Foundry key, storage account key, Chatwoot API key were leaked into the conversation transcript before I caught it). Always use `--query "[].name"` for audits.
- **Process evaluators (Task Adherence / Intent Resolution / Tool Call Accuracy) need azure-ai-projects 2.0.1 + a registered eval definition** in the Foundry portal catalog. `scripts/create_foundry_custom_eval.py` (already in repo) registers a 7-quality + 5-safety + 6-string_check eval with grok-4-1-fast-reasoning judge. The new `run_foundry_native_eval.py` triggers eval runs via the SDK.
- **Latency lever ranking (cs-agent, observed):** dropping `memory_search_preview` is the dominant win (~1.5-3s/turn). `tool_choice: required → auto` saves ~0.5-1s on greetings. `reasoning.effort: low → medium` reduces Content Safety retry loops (paradoxically faster on average). Expected impact mostly confirmed by data.
- **The application endpoint config can NOT be changed via REST.** Only Portal. Pivoted operator advice toward `AZURE_AI_FOUNDRY_ROUTE_MODE=agent` (route ALL traffic through the controllable surface) instead of trying to fix application config.
- **`create_ticket` already returned HTTP 410 unconditionally since v101 deploy** (~Apr 20). Dev-test POST that produced the Apr-16 leak fired BEFORE that deploy. Post-deploy, no path remained for the same leak.
